Summary of goals and high-level design:
Design an incremental build core that minimizes redundant work when exploring large, parameterized configuration spaces by combining precise dependency tracking, content-addressable caching, action fingerprinting, and tight instrumentation hooks for search guidance. The core must be correct (reproducible builds), scalable (millions of nodes/artifacts), and flexible to support many configurations without full rebuilds.

Core model and dependency tracking:
Represent the build as a directed acyclic graph of tasks (actions) and artifacts where each node is content-addressable. Distinguish declared dependencies (explicit inputs) from inferred dependencies (discovered at runtime or via sandboxing). Compute for each action a fingerprint composed of: action identity (command, env subset, tool versions), ordered input fingerprints (content hashes), and relevant configuration keys. Track fine-grained outputs so partial outputs can be reused across different downstream actions and configurations.

Change detection and action fingerprinting:
Use content hashing as primary change detector; fall back to hybrid mtime+size for quick checks and to short-circuit known-unchanged blobs. Generate strong action fingerprints: hash of command+flags+tool binary hash+sorted input content hashes+configuration key. Recompute only when fingerprints change. For non-hermetic actions, provide sandboxing/emulation or conservative invalidation.

Caching strategy and provenance:
Maintain a content-addressable cache (local and optional remote) mapping action fingerprints to produced artifacts and provenance metadata (input fingerprints, environment, timestamp). Support multi-dimensional cache keys to capture configuration parameters so identical subgraphs across different configurations reuse artifacts. Store compact provenance and a transitive digest for quick equivalence checks. Allow lazy materialization: fetch artifacts into workspace on demand.

Incremental scheduling and execution:
Perform incremental topological traversal starting from requested targets, skipping subgraphs whose fingerprints match cache entries. Support parallel execution, prioritize cheap/impactful nodes, and use cost estimates per node to minimize wall time during search-driven exploration. Support partial rebuilds and fragment reuse when configurations diverge only on parts of the graph.

Cache invalidation and eviction:
Prefer precise invalidation via fingerprint mismatch. Provide conservative fallbacks (invalidate entire subtree) only when provenance is incomplete. Eviction policies include size- and cost-aware LRU, and guidance-driven retention: search controller can pin high-value artifacts. Support TTLs and background prefetch/refresh for hot artifacts.

Instrumentation and interfaces for search guidance:
Expose events (node started/finished, cache hit/miss, cost, artifact size, provenance) via streaming API. Provide query APIs for DAG structure, fingerprints, cache statistics, and estimated recompute cost. Allow the search controller to influence scheduling (prioritize nodes), cache retention (pin/unpin), and sampling strategies (speculative builds). Record compact traces to enable replay and cost modeling.

Open research gaps:
Efficient semantics for cross-configuration artifact reuse, delta-builds for parameterized actions, provenance compression for long explorations, and probabilistic heuristics to balance cache space vs expected reuse. These are promising directions to minimize work in large configuration-space exploration.
