The model must be hermetic (actions fully described), deterministic where possible, and efficient to compute/compare fingerprints at scale.

Core concepts and semantics:
- Action fingerprint: For each build task T under configuration C, compute a cryptographic fingerprint F(T,C) = H(command-line, environment variables, toolchain/version IDs, explicit parameters from C, sorted list of dependency fingerprints, and any declared non-file inputs). This fingerprint is the single-source validity token for reuse.
- Observed dependencies: During execution, capture file-system accesses and other side effects to extend the dependency record. Observed dependencies become part of future fingerprints so dynamic deps are tracked.
- Correctness/invalidation rule: A cached artifact for (T,C) is valid iff the stored fingerprint equals current F(T,C). If any underlying input changes (content or tool/version), dependent tasks’ fingerprints change and they become invalidated.
- Provenance: Store for each artifact the action descriptor, observed deps, and the artifact in a content-addressable store (CAS). That enables remote/shared caches and precise reconstruction.

Operational algorithm (high-level):
1. Graph evaluation: Represent build as a DAG parameterized by configuration values; nodes are parametric tasks.
2. Bottom-up fingerprinting: For leaf inputs compute input fingerprints (content hashes or version tokens). For each node, compute F(T,C) from its action descriptor and child fingerprints.
3. Cache check: Query action cache keyed by F(T,C). If hit, materialize artifact from CAS; mark node as reused. If miss, check for partial reuse opportunities (see below), otherwise schedule execution.
4. Execute in isolated sandbox to record observed deps and produce outputs; compute final fingerprint and store outputs and metadata in CAS and action cache.
5. Propagation: When a base input changes, recompute fingerprints upward and only re-execute nodes whose fingerprints changed.

Techniques for scaling across config spaces:
- Task decomposition: Split tasks into config-invariant and config-specific phases (e.g., frontend parsing vs backend codegen) so invariant phases can be reused across many configs.
- Layered fingerprints: allow partial keys for invariant subgraph reuse; finalization step consumes invariant artifact + config-specific fingerprint to produce final output.
- Approximate reuse and patching: for similar configs, attempt binary patching or delta-reuse of outputs when deterministic transformation allows (tool-specific).
- Cache indexing: maintain compact indices (Bloom filters, LRU tiers) to avoid expensive CAS lookups at scale.

Robustness and practical considerations:
- Include tool-versioning and environment in fingerprints to prevent silent corruption.
