Label taxonomy (ground-truth classes)
- Direct connection: a metal or net joining pins (wire/net membership).  
- Functional coupling: intended signal path (input→gain stage→output) as distinct from incidental connectivity.  
- Feedback path: loop that returns output-related node to an earlier stage (explicit resistor/capacitor or transistor path).  
- Bias relationship: nodes that set DC operating point (current mirrors, bias resistors, reference nodes).  
- Mirror/matched pair: transistors forming mirror or differential pair relationships (device-pair semantics).  
- Power/ground rails: supply and substrate ties (treated separately from signals).  
- AC coupling: capacitor-mediated coupling (blocks DC but passes AC).  
- Parasitic/noise coupling: proximity or substrate coupling (for advanced labels).  
- Block membership: node/device belongs to same functional block (op amp, filter, bias core).

Annotation rules and heuristics
- Build a bipartite graph: device-pin nodes + net nodes; derive higher-level node abstractions (blocks, ports) when hierarchical info exists.  
- Use netlist semantics: net names, pin names, device types heavily inform labels (e.g., “Vout”, “Vbias”).  
- Feedback label requires closed loop path where a device/net connects output-like node back to input-like node and affects transfer function; verify by small-signal loop traversal or simulation.  
- Bias label requires sustained DC current/voltage contribution — confirm via DC operating point.  
- Differentiate rails: any net tied to global supply symbols or large decoupling capacitors should be rail-labeled and excluded from being treated as signal links.  
- For ambiguous cases, prefer conservative labeling (no functional link) unless simulation confirms.

Validation methodology (ground truth confirmation)
- Cross-check schematic-based annotations with SPICE netlist parsing.  
- Use DC operating point and AC/PTF (transfer function) analysis to confirm biasing and functional coupling: perturb input small-signal and observe node gains to validate predicted signal paths and feedback.  
- Use current-flow checks for mirror pairs (matching currents under bias conditions).  
- Flag any predicted direct connection that would short supplies or violate device pin types as topologically invalid.

Failure modes and interpretations
- False positives linking rails to signals: typically due to net-name overlaps or learned correlations; mitigate by explicit rail features and masking.  
- Missing high-impedance links (floating nodes): GNNs may underpredict; augment features with DC impedance and device stack info.

Metrics and priorities
