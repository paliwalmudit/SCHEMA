Core model
- Represent the build as a directed acyclic hypergraph where nodes are actions (commands) parameterized by a configuration vector and edges are explicit file/resource dependencies. Incremental semantics and change propagation
- Change detection uses two orthogonal signals: file content fingerprints (content hashes) and config diffs (typed, structured config changes). On update, compute changed node keys and perform a demand-driven, reproducible graph traversal to compute the minimal affected subgraph.
- Scheduler is lazy/eager hybrid: default demand-driven (only build requested targets), with optional eager propagation for CI or batched explorations across many configs.

Consistency guarantees

Incremental Algorithms Researcher: "The summary proposal is strong; I propose precise algorithms, formal properties, complexity bounds, and practical heuristics to make the model provably minimal and implementable at scale.

Model and notation
Represent the build as a directed acyclic hypergraph G = (V,H) where each hyperedge h ∈ H maps a set of input nodes to one output node. Each node v ∈ V is keyed by K(v) = H_cmd(action, toolchain_fingerprint, declared_inputs_fingerprints, π_v(cfg)), where π_v is the projection of configuration that v declares it depends on. Let cfg_old and cfg_new be two configurations.

Change-detection algorithm (high level)
1. Compute file/content changes S_files = {v | fingerprint(inputs(v)) changed}.
2. Compute config diff D = diff(cfg_old,cfg_new).
3. Compute S_cfg = {v | π_v(D) ≠ ∅} — nodes whose declared config fragment intersects D.
4. Seed S0 = S_files ∪ S_cfg.
5. Compute affected set A = transitive-closure_forward(S0) over G (i.e., all nodes reachable from S0).
6. For each v ∈ A recompute K(v); if cache contains artifact for K(v) skip execution, else schedule v for execution following topological order.

Correctness and minimality
- Soundness: If all declared inputs (including π_v(cfg) and toolchain fingerprint) and hermetic execution hold, any cached artifact returned by matching K(v) is semantically valid because K(v) is collision-resistant and includes all influencing inputs.
- Completeness: Any v that transitively depends on changed inputs or changed π_v(cfg) is in A by construction and will be considered; if a cached artifact with the new K(v) exists, it replaces rebuilding.
- Minimality proof sketch: Under the assumption that π_v correctly captures v’s config sensitivity and declared inputs capture all file dependencies, no node outside A can have inputs or config fragments that changed, so rebuilding them is unnecessary. Thus the algorithm schedules exactly A \ C where C = {v ∈ A | cache contains K(v)}.

Complexity
Computing S_files and S_cfg is O(|V_changed_inputs| + |V|·cost(π_v evaluation)) where evaluating π_v is constant-time for typed fragments. Transitive closure is O(|E_A|+|V_A|) where A is the affected subgraph. In practice cost scales with exposed locality: if changes touch small cfg fragments, |A| ≪ |V|.

Practical heuristics
- Sensitivity inference: infer π_v by static analysis + runtime tracing; refine π_v conservatively initially, then specialize using counterexample runs to shrink π_v and increase reuse.
- Product caching: factor keys as K(v) = H_base(v) || H_cfg(π_v(cfg)) to allow layered CAS and delta artifacts; use content-diff patches for similar artifacts across configurations.
- Scheduler: demand-driven default, with batched eager scheduling for CI; use parallel topological execution with prioritized frontier (nodes with high rebuild cost first).
- Safety: runtime hermeticity checks and sandboxed execution; on detection of undeclared side-effects, escalate to conservative π_v := full-config.

Prototype and evaluation
Implement prototype that exposes query APIs (affected-subgraph, key-diff), supports CAS and layered artifacts, and benchmarks cache-hit rate, |A|, and wall-time across configuration-space tilings. Measure amortized rebuild cost under locality models (e.g., k-local config perturbations) to validate expected savings.

I can formalize the minimality proof and provide pseudocode and complexity proofs for the transitive-closure and incremental maintenance of π_v sensitivity on request."
